# DigitZip

A macOS Finder Sync extension plus a small background app that adds 7-Zip-style **Extract Here** and **Extract to “name/”** and **Add to “name.zip” / “name.7z”** items to Finder's right-click menu, under a **DigitZip ▸** submenu. See README.md for the user-facing behavior.

**Use US English spelling** everywhere: UI text, code, comments, docs and commit messages (behavior, color, canceled, recognize, license).

## Build

- Requirements: Xcode, plus `brew install xcodegen sevenzip`.
- `scripts/build.sh` regenerates the project and builds Debug into `./build`. `scripts/build.sh --install` also copies the app to `~/Applications` and launches it.
- Quick compile check without a full build: `xcrun swiftc -typecheck -target arm64-apple-macos14.0 Shared/*.swift App/*.swift`

## Project rules

- **Edit `project.yml`, never `DigitZip.xcodeproj`.** The project is generated by XcodeGen and git-ignored. XcodeGen also rewrites `App/Info.plist`, `FinderExtension/Info.plist` and both `.entitlements` files from `project.yml`, so change their contents there.
- Signing settings (team ID or certificate name) go in `Config/Local.xcconfig` (git-ignored, template in `Config/Local.xcconfig.example`). Never put signing settings in `project.yml`: project-level settings there would override the xcconfig.
- The `7zz` binary is never committed. A post-build script in `project.yml` copies it from Homebrew into `Contents/MacOS/` and signs it.
- Swift 5 language mode, macOS 14+ deployment target. UI and the job queue are `@MainActor`, and process work runs in `Task.detached` (see `SevenZip.pipeline`).

## Architecture

```
Finder → FinderExtension/FinderSync.swift   (sandboxed; only builds the menu)
           │ NSWorkspace.open(digitzip://extract|compress|about?…&files=<base64url JSON paths>)
           ▼
         App/AppDelegate.swift              (LSUIElement app; non-sandboxed)
           → App/JobQueue.swift             (extract/compress jobs one at a time; prompts; notifications)
           → App/AddToArchiveWindow.swift   (Add to Archive… dialog; options in App/CompressionSettings.swift)
           → App/SevenZip.swift             (runs bundled 7zz: piped stages, live progress, cancellation)
           → App/ProgressPanel.swift        (floating progress window with Cancel)
```

- `Shared/ArchiveTypes.swift` is compiled into both targets. It holds the supported extensions, tarball detection, `baseName` (folder naming), and the `DigitZipRequest` URL encode/decode. Keep both sides in sync by changing only this file.
- The extension is sandboxed and must not try to write files. All file work happens in the app.
- The app shows the settings window only on a normal launch (`launchIsDefaultUserInfoKey`). When launched by URL it stays hidden and quits 30 s after the queue goes idle.

## 7zz conventions (verified against 7-Zip 26.06)

- Always pass a `-p…` switch (`-pDIGITZIP-NO-PASSWORD` when none) and give stdin `/dev/null`, so 7zz can never block on a password prompt.
- Password errors read `Wrong password` (encrypted entries) or `Cannot open encrypted archive` (encrypted headers). `ProcessResult.isPasswordError` checks both.
- Progress: `SevenZip.run(…, onProgress:)` swaps `-bd` for `-bsp2` and parses the backspace-redrawn " 32% 2 + file" segments from stderr. They're stripped from `errorOutput` afterward.
- Cancel: each job runs in its own Task, and canceling it sends SIGTERM to 7zz. 7zz exits 255 ("Break signaled"), leaving an updated archive untouched and not leaving a half-written new one. `SevenZip` then throws `CancellationError`, and job functions clean up their staging and return `.canceled`.
- Exit code 0 = OK, 1 = warnings (treated as success), 2 or higher = failure.
- Tarballs (`.tar.gz`, `.tgz`, …) run as two stages: `x -so` piped into `x -si -ttar`.
- "Extract to folder" extracts into a hidden `.DigitZip-<uuid>` staging folder next to the archive, then moves it into place (`moveStagedContents`). If the archive held exactly one folder, that folder becomes the destination (smart folder).
- "Add to name.zip/.7z" writes a hidden `.DigitZip-<uuid>.zip` staging file next to the items, then renames it (`name 2.zip` if taken). Naming follows 7-Zip: one file → name without extension, one folder → its name, several → the parent folder's name.
- `CompressionSettings` / `CustomCompression` (App/CompressionSettings.swift) turn dialog choices into 7zz switches with no UI code, so they can be tested by compiling that file with Shared/ and running 7zz. In `AddToArchiveModel`, never assign `settings` unconditionally inside its own `didSet`: @Published re-runs didSet and it recurses forever.
- Extraction always excludes `__MACOSX` and `._*` (`-xr!__MACOSX -xr!._*`).
